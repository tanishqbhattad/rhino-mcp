# RhinoAIBridge — Deep Audit, Fixes & v4.8.0 Protocol 5 (2026-06-13)

> **Update:** the full improvement roadmap at the bottom of this document has now been IMPLEMENTED — see `RELEASE_NOTES_v4.8.0.md` for the shipped feature list. Highlights: multiplexed protocol 5 (reads/ping/cancel answer while long commands run), idempotent retries via request_id replay (duplicate-execution risk eliminated for every command), cooperative cancellation (`cancel_operation`), binary image frames (flag 0x02, no base64 inflation), ViewCapture offscreen rendering, FileIO-based 3dm export + crash-safe checkpoint restore, geometry post-conditions on every create/boolean, oriented (diagonal-wall-correct) opening placement, cached whole-scene validation, unit-aware defaults, columnar `query_scene` (40-60% token cut), plan+front thumbnails on big batches, persistent checkpoint registry with auto-prune + `delete_checkpoint`, and a write-ahead log with `get_recovery_log`. Both sides remain backward compatible with protocol 4 peers. Verified: 53/53 offline tests pass; all Python compiles; C# changes are balanced and cross-referenced (rebuild with `dotnet build -c Release`).

Full-repo audit: Python MCP server (`server/`), C# plugin (`plugin/`), installers, tests, CI. The previously documented audit items (DEEP_AUDIT_2026-06-10) were confirmed fixed; the issues below are **new findings**, all patched in this tree unless marked otherwise.

## Bugs found and fixed

### Critical — correctness / data loss

**1. Silent duplicate execution of mutating commands on reconnect** (`protocol.py`)
`send_command`/`send_batch` retried after any connection error — including errors that happened *after* the request frame reached Rhino. If a wall-creation batch executed but the response was lost, the retry re-ran the whole batch, silently duplicating every object. Fixed: a per-attempt `sent` flag distinguishes "failed before write" (safe to retry — covers the common Rhino-restarted case) from "possibly delivered" (mutating commands now raise an explicit "may have already executed — verify with query_scene" error; a whitelist of read-only commands still retries transparently).

**2. `ping` killed in-flight commands** (`protocol.py`)
A ping issued while a long batch/script (up to 180 s) held the connection lock would time out and call `disconnect()`, closing the socket out from under the running command. Fixed: ping now tries the lock with a timeout and answers `{"status":"ok","busy":true}` without touching the socket; it only disconnects on a real socket failure.

**3. `restore_checkpoint` could wipe the entire model** (`CommandHandler.cs`)
It deleted *all* objects first, then ran `-_Import`. If the import failed, the user was left with an empty document. Fixed: import first (imported objects get fresh GUIDs), verify success, then delete the pre-existing objects; on failure the current geometry is left untouched and a typed `RESTORE_FAILED` error is returned.

**4. 60-second idle disconnect of the persistent MCP connection** (`AIBridgeServer.cs`)
`ReceiveTimeout = 60s` applied forever, but the MCP client keeps one persistent connection that legitimately idles for minutes between user turns. Every quiet pause forced a teardown, and the next command went through the reconnect/retry path — the same path that risked duplicate execution (#1). Fixed: the 60 s timeout now only guards unauthenticated/idle-from-birth sockets; it's lifted after the first valid authenticated command.

### High — wrong results

**5. `export_objects` was broken for "all objects" and reported false success** (`CommandHandler.cs`)
`-_Export` operates on the current selection, but the all-objects path selected nothing — the scripted command stalled at the object prompt and no file was written, while the tool still returned `status: ok`. Fixed: explicit selection in both paths, file-existence verification, typed `EXPORT_FAILED` error, dead duplicated code removed.

**6. `calibrate_scale` could double-transform objects** (`CommandHandler.cs`)
It called `Doc.Objects.Transform(..., deleteOriginal: true)` while live-enumerating the object table; replacement objects could be re-visited and scaled twice. Fixed: IDs materialized to a list before transforming; success now counted per actual transform.

**7. `get_scene_diff` silently returned incomplete diffs** (`ChangeTracker.cs`)
The change log is a 1000-event ring buffer. If events older than `from_version` had been evicted, the diff was partial with no indication — an agent syncing against it would believe nothing else changed. Fixed: `GetDiff` detects eviction and the response carries `log_truncated: true` plus a warning to fall back to `query_scene`.

**8. Stale type index after object replacement** (`SceneSnapshot.cs`)
`OnReplaced` updated `meta.Type` but not the `_byType` index, so type-filtered queries missed objects whose geometry type changed (e.g. curve → brep). Fixed: index re-keyed on type change.

**9. `RHINO_HOST`/`RHINO_PORT` only affected the heartbeat, not the connection** (`protocol.py`)
The watchdog honored the env vars; the actual command connection hard-coded `127.0.0.1:9544`. On a custom port, the heartbeat watched one port while commands went to another. Fixed: both now read the same env vars.

### Medium — fidelity / consistency

**10. `capture_inspection_view` reset the user's lens to 50 mm** (`CommandHandler.cs`) — the restore path hard-coded `ChangeToPerspectiveProjection(true, 50)`. Fixed: lens length saved and restored.

**11. `boolean_operation` deleted inputs before adding results** (`CommandHandler.cs`) — an exception in `AddBrep` lost both inputs (recoverable only via undo). Fixed: results added first, inputs deleted after.

**12. `thumbnail` default contradicted its MCP contract** (`CommandHandler.cs`) — C# defaulted `wireframe=true`, tool docs say Shaded default. Fixed to `false` (raw/batch callers now match documented behavior).

**13. `export_objects` mis-annotated `readOnlyHint: true`** (`server.py`) — it writes files and mutates selection. Changed to a write annotation.

**14. `execute_python3` pinged Rhino twice per call** (`server.py`) — `_developer_mode_required` and the version check each did a round-trip. Merged into one.

**15. Stale "wait forever" comment on the bounded heartbeat startup loop** (`server.py`) — fixed.

### Noted, not changed (low risk / design decisions)

`JobManager.cs` is dead code (never referenced) — delete it or wire it in. `place_openings_on_facade` assumes axis-aligned walls (uses bbox long axis; diagonal walls get mis-positioned openings). `batch_layer_visibility` isolate matches short layer names only and ignores parent-layer visibility. `check_intersection` is bbox-only (documented, but a `precise: true` mode using `Intersection.BrepBrep` would be cheap to add). `LayerEntry` Pydantic model defined but unused by `create_layer_tree`. The `batch_preview` docstring has `$N` placeholders stripped from text. IronPython preamble shifts script line numbers in tracebacks (~12 lines) — worth surfacing the offset in error responses.

## Roadmap: toward the fastest, most accurate Rhino MCP

**Speed**

- *Multiplexed protocol (your deferred Phase 4) is now worth doing.* Single-flighting means a 180 s script blocks every read. Add `request_id` to frames and a futures table client-side; on the plugin, reads served from `SceneSnapshot` (query_scene, list_layers, ping-with-doc-info) can answer from the TCP thread without the UI hop, so reads stay sub-ms even while a mutation runs. This also makes ping-while-busy trivial.
- *Offscreen capture.* `CaptureViewport` mutates the live viewport and redraws twice (capture + restore). Render to a detached `RhinoViewport`/`ViewCaptureSettings` offscreen: no user-visible flicker, no restore path, and captures become parallelizable — `capture_review_set`'s 5 sequential captures collapse to one round-trip.
- *Replace `RunScript("-_Export ...")`/`-_Import` with `FileIO` APIs* (`FileStl.Write`, `File3dm`): no command-line scripting fragility, real error reporting, no selection churn.
- *Binary frames for images.* Base64 inflates captures 33% and JSON-parses them as strings. Add flag `0x02` = raw image payload with a small JSON header; wire format already supports flags.
- *System.Text.Json source generators (your Phase 7)* for the hot paths only (query_scene/batch responses) — keep Newtonsoft elsewhere.

**Accuracy**

- *Request sequence numbers + result cache.* The real fix for duplicate execution: client stamps each mutating command with a GUID; plugin keeps the last N results keyed by GUID and replays the stored response on re-send. Then retries become safe for everything, not just reads.
- *Geometry post-conditions.* After create/boolean ops, return `is_solid`, `is_valid`, and face/edge counts so the model can detect bad geometry without a follow-up call (you already do this for booleans inside scripts — generalize it).
- *Oriented-bbox facade placement* for `place_openings_on_facade` (project wall onto its own long axis via plane fit) so diagonal/curved walls work.
- *Per-object validity cache in SceneSnapshot* (your deferred Phase 5 item) so `validate_objects` covers 5000-object scenes instead of capping at 100.
- *Unit-aware inputs everywhere*: tools assume mm in several defaults; read `ModelUnitSystem` once per command and scale defaults (you do this in `calibrate_scale` only).

**Efficiency / agent ergonomics**

- *Pack `scene_version` + a 4-view low-res thumbnail strip into batch responses* so the model self-verifies without extra calls (the auto-thumbnail is great — extend it with plan/front when batch size > N).
- *Token-lean object listings*: emit columnar arrays (`ids: [...], layers: [...], bboxes: [...]`) instead of repeated per-object JSON keys — typically a 40-60% token cut on large `query_scene` results.
- *Checkpoint hygiene*: auto-checkpoints accumulate forever in `%TEMP%\aibridge_checkpoints` and the registry is per-session (restored sessions lose names). Persist the registry to a JSON sidecar, cap auto-checkpoints (e.g. keep last 10), and add `delete_checkpoint`.
- *Structured cancellation* (your audit's finding 4): per-command operation IDs + a `cancel` frame; long loops in DeriveFloors/PlaceOpenings check a token between iterations.
- *Crash-safe write-ahead log*: append each mutating command to a session log before execution; after a Rhino crash, the agent can replay/diff to recover context.
